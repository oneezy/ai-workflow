# Where harness release news can be read automatically

Research for wayfinder ticket oneezy/ai-workflow#10. Checked 2026-10-03 from a Claude Code cloud session (curl through the agent proxy, plus WebFetch for github.com pages the session's repo-scoped GitHub access refuses).

## Answer

Every source below can be read without logging in, but the formats are not the same. **Claude Code** has the best feeds. It publishes `CHANGELOG.md` in its GitHub repo, and the docs site regenerates that file as an RSS feed (`code.claude.com/docs/en/changelog/rss.xml`) and as raw Markdown. The npm registry (`@anthropic-ai/claude-code`, with `latest`/`stable`/`next` dist-tags) and a plain-text channel endpoint give the version numbers. It ships about once each weekday. **OpenAI Codex** has no real `CHANGELOG.md`. Its CLI notes live in GitHub Releases, which also carry several alpha releases a day. The npm registry (`@openai/codex`) covers versions. Everything else goes into one combined "ChatGPT & Codex changelog" RSS feed, which also mirrors each stable CLI release: Codex cloud, the Codex/ChatGPT desktop app, models and deprecations. **The ChatGPT desktop app** merged with the Codex app on 2026-07-09. Its notes now go into that same combined RSS feed, and its macOS builds show up in a Sparkle appcast (undocumented, versions only). The old help-center release-notes articles return a bot challenge (403) to scripts. **The Agent Skills spec** and **AGENTS.md** have no versions, releases or changelog. The only machine-readable signal is the GitHub commit Atom feed of the repo, which can be filtered to the spec file. Both change about monthly or less often. **Matt Pocock's skills** uses changesets. It has a `CHANGELOG.md`, GitHub Releases with an Atom feed, and a version in `.claude-plugin/plugin.json`. It is not on npm (`"private": true`). It releases roughly monthly, with commits most weeks. A scheduled agent or GitHub Action needs nothing more than RSS/Atom parsing plus `curl` on raw.githubusercontent.com and registry.npmjs.org. GitHub's REST API also works without a token, but only for 60 requests an hour; in an Action, `GITHUB_TOKEN` raises that to 1,000.

## Notes

- **Scheduled agent vs GitHub Action.** Every URL above except help.openai.com is a plain anonymous GET. In a GitHub Action, `curl` + an RSS/Atom parser is enough. The REST API (`/repos/{o}/{r}/releases`) also works anonymously at 60 requests/hour per IP, and with the built-in `GITHUB_TOKEN` at 1,000 requests/hour per repository. In *this* cloud sandbox, github.com, api.github.com and the `gh` CLI return 403 because session GitHub access is limited to the configured `oneezy/*` repos. That is a sandbox policy, not a GitHub login requirement. raw.githubusercontent.com is not affected, and WebFetch reached the github.com Atom feeds. A scheduled cloud agent here should therefore use raw.githubusercontent.com, the docs-site RSS feeds and npm, or have the repos added to the environment. A GitHub Action has no such limit.
- **Claude Code** has three equivalent change sources (CHANGELOG.md, docs RSS, docs .md), all fed from the same file. The docs `.md` page says so: "This page is generated from the CHANGELOG.md on GitHub". The RSS adds a `pubDate` per version, which CHANGELOG.md lacks. The `stable` channel trails `latest` by a few versions (2.1.285 vs 2.1.288), so a watcher should decide which channel it reports. The page links its RSS feed through `<link rel="alternate" type="application/rss+xml">`. `docs.anthropic.com/en/release-notes/claude-code` redirects to the GitHub CHANGELOG. The API/platform release notes at https://platform.claude.com/docs/en/release-notes/overview are a separate product and out of scope.
- **Codex** release notes are split. The CLI's changelog *is* its GitHub Releases (the repo's CHANGELOG.md says "The changelog can be found on the releases page"). The combined RSS feed embeds those release bodies (`guid` `#github-release-<id>`), so subscribing to the RSS alone covers the CLI stable releases without the alpha noise. The RSS also covers Codex cloud (for example "GitLab support in Codex cloud (Beta)", 2026-08-19), the desktop app, iOS, models and deprecations. Codex cloud has no version numbers of its own. The feed has no categories, even though the HTML page tags every item `data-product="codex"` and filters by `type`. A consumer that wants only "Codex cloud" or "desktop app" must classify by title and body.
- **ChatGPT desktop app.** "Codex joins the ChatGPT desktop app" (RSS, 2026-07-09): Codex is now part of the ChatGPT desktop app on macOS and Windows, and a Linux preview was announced 2026-08-11. The legacy ChatGPT macOS appcast was renamed "ChatGPT Classic" and stops at 2026-07-15. The current macOS updater feed `codex-app-prod/appcast.xml` serves `ChatGPT-darwin-arm64-*.zip` builds. Its URL is not documented anywhere I found; I discovered it by probing, so it can break without notice. Use it only as a "new build exists" signal. No Windows (Microsoft Store) feed was checked or found. The help-center release-notes articles may still be updated, but they cannot be read by scripts.
- **Agent Skills** (agentskills.io) is a Mintlify site built from `github.com/agentskills/agentskills` (`docs/specification.mdx`). The repo has no tags or releases. Most commits add clients to the showcase, so the path-filtered commit Atom feed is the right watch target. PyPI `skills-ref` still lists `github.com/anthropics/agentskills` as its repository (the repo's earlier home). `agentskills.io/llms.txt` lists every docs page as `.md`.
- **AGENTS.md** is a Next.js site in `github.com/agentsmd/agents.md`. The "standard" is the site's prose, with no versioning. The most recent substantive change was a Technical Charter PDF (2026-09-10). The npm package `agents-md` is an unrelated third-party library (`ivawzh/agents-md`); ignore it.
- **Matt Pocock's skills** ships as a Claude Code plugin (`claude plugins install mattpocock-skills`, from the official marketplace, auto-updating) and through `npx skills@latest add mattpocock/skills` (skills.sh). Versioning is changesets with `privatePackages: { version: true, tag: true }`, so each release produces a CHANGELOG entry, a git tag and a GitHub release. `release/v1.3` was merged to main on 2026-09-29, but `package.json`/`plugin.json` still read 1.2.3 and no v1.3 tag exists, so a v1.3 release looks imminent. The README also links a newsletter (aihero.dev), which is email and not machine-readable.
- **Cadence figures** come from npm `time` fields, feed timestamps and commit feeds, all read on 2026-10-03. They are observations over the visible window, not stated policies.
